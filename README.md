## 3. 配色对齐（本轮主要工作）

做法不是"看着调"，而是**先从参考图取样，再用光学换算反推材质基色**：

```
参考图实测（sRGB）                  用途
背景/地面  #F6EBDF (246,235,223)   摄影棚底色
车身奶白   #EBDACA (235,218,202)   珍珠象牙白
腰线       #C79B72 (199,155,114)   香槟驼色（非金属亮金）
下裙       #564A42 (86,74,66)      深暖灰（不是黑色）
窗内暖光   #EDB462 (237,180,98)    车内灯带
轮胎       #211C19 (33,28,25)
轮圈       #8E725D (142,114,93)    暗青铜
```

关键换算：场景由**近似均匀的暖奶油环境**照明，此时

> 漫反射表面的渲染值 = 反照率 × 环境辐亮度
> 所以 **albedo_linear = target_linear / ENV**

`rv/lib_mat.py` 里的 `alb()` 就干这件事，`ENV` 是唯一总控旋钮——渲染偏亮/偏暗只需改 ENV，所有材质等比跟随。

**最终色差（`tools/match.py`，单位 0–255）：**

| 特征 | 参考 | 渲染 | Δ |
| --- | --- | --- | --- |
| 车身上部 | #EBDCCE | #EBDACB | **1.7** |
| 车身下部 | #ECDACA | #E7D6C7 | **4.0** |
| 腰线 | #CFAB89 | #D7AA80 | **6.0** |
| 下裙 | #574A42 | #4C453F | **6.3** |
| 下裙下缘 | #5C4F48 | #504841 | **8.7** |
| 轮胎 | #302923 | #2A2623 | **3.0** |
| 轮圈 | #8E725D | #876B56 | **7.0** |
| 车窗 | #764620 | #675344 | 21.3 |

**平均色差 7.3 / 255（约 2.9%）**，迭代起点是 129。

## 4. 迭代记录（33 轮，m01 → m33）

| 轮次 | 主要问题 | 处置 |
| --- | --- | --- |
| m01 | 车身惨白、下裙发灰 | 换 Standard 色调映射（原来的 AgX 一直在洗掉颜色）+ 按实测值重建材质库 |
| m02–m03 | 整体过曝 | 发现**面积光实测照度是点光公式的 4 倍**；地板自发光又叠加在漫反射之上，把背景顶爆 |
| m04 | 下裙仍然太亮 | 射线诊断定位：**车内灯从车窗洞口漏光**照亮了下裙 |
| m05–m06 | 下裙色阶不对 | 改三段 Z 渐变；车内灯增益降到 0，改由自发光灯带提供窗内暖光 |
| m07–m09 | 车窗是一块灰板 | 加琥珀发光背板 + 窗内结构件；顺带修掉**灯光朝向向量取反**（面光一直背着主体照） |
| m10–m12 | 车窗不够暖 | 用 Generated.Z 驱动的发光渐变背板，模拟"下亮上暗"的灯槽 |
| m13–m16 | 机位与参考差太多 | 用主体包围盒长宽比标定仰角；发现参考用了**广角近距**（透视很强） |
| m17–m20 | 焦距/构图 | 试 36/42/50mm，定在 45–50mm |
| m21–m26 | 车窗里看不出是房间 | 加入床、厨台、沙发、吧台的**背光剪影**；木纹换成素面橡木（缩到窗外尺度后木纹只会变成噪点） |
| m27–m29 | 阴影与车窗对比 | 主光取值折中；车窗上 2/3 压深（对应参考图里的树影反射） |
| m30–m33 | 构图裁切 | 让车身轻微出血，贴近参考图的取景 |

## 5. 最终版相对初版的改进（本轮）

1. **色调映射**：AgX → Standard。AgX 在持续压缩与去饱和，是"颜色怎么调都不对"的根因。
2. **配色**：全部材质改用参考图实测值 + 光学换算，平均色差从 129 降到 7.3。
3. **下裙**：从近黑改为深暖灰 #564A42，并加三段 Z 渐变 + 舱门凹槽 + 拉手 + 琥珀标志灯 + 顶部阴影缝。
4. **腰线**：从亮金改为哑光驼色 #C79B72，加宽到 7cm。
5. **车窗**：上 2/3 深色（树影反射）、下部透出暖光内装，内部有床/厨台/沙发/吧台剪影与灯槽亮线。
6. **灯光 bug**：修掉面光朝向取反（此前所有补光都背着主体照，是画面发平的另一半原因）。
7. **机位**：仰角 30° → 9–13°，焦距 85 → 48mm，得到参考图那种强透视近景。

## 6. 已知边界

* 尺寸、载荷与可制造性未做工程验证——沿用参考图集定位：**二维视觉设定转三维，非可生产图纸**。
* 无人机升降平台与防御炮塔为影视道具外形，不含任何机械/武器控制方案。
* 车窗内部为"背光剪影"处理（保证车外视角下读出暖色内装），不是可进入的完整室内；参考图集里的室内另有专门图版。
* Eevee 阴影池上限 2048 tile，车内补光已全部 `use_shadow=False`。

## 7. 可交互网页版（走进车内）

仓库根目录的 `index.html` 是一个 Three.js 单页应用，可在浏览器里实际操控模型。

**线上地址**：https://starpark-coach-3d.app.workbuddy.host/

**线上地址**：https://starpark-coach-3d.app.workbuddy.host/

**入口**：`index.html`（3D 交互） · `gallery.html`（渲染图集与迭代记录）

| 功能 | 说明 |
| --- | --- |
| 外部环绕 | 拖拽旋转、滚轮缩放、右键平移；左侧快捷机位（主视角 / 车头 / 车尾 / 侧面 / 车顶 / 底盘） |
| **进入车内** | 第一人称漫游：WASD 移动、鼠标转视角、Shift 加速、Esc 退出；也可从左侧直接进入驾驶舱 / 会客区 / 厨房 / 卧铺 |
| **剖切** | 用 Three.js 裁剪平面把靠近相机的一半外壳实时切开，可绕着车走看内部结构 |
| 车顶设备 | 一键隐藏车顶装备，便于看车顶本体 |
| 自动旋转 | 转台式展示 |

**模型导出** `export_web.py`：程序化节点材质无法直接进 glTF，脚本把每个材质替换成扁平 PBR
（颜色仍取自同一套参考图实测色板），并按
`SHELL / XD / ROOF / CHAS / INT / BODY` 分组、按（组，材质）合并网格，
87 个网格 / 3.6 MB。分组前缀让网页端能做「剖切」与「进车内自动隐藏窗外装饰」。

**本地预览**（必须走 http，直接双击本地文件会被跨域策略拦掉）：

```bash
python -m http.server 8000
# 打开 http://127.0.0.1:8000/index.html
```

**验证** `tools/verify_web.js`：用 Playwright 无头浏览器跑一遍——载入模型、检查控制台报错、
逐项截图（外部 / 车顶 / 剖切 / 驾驶舱 / 会客区 / 卧铺），截图存 `tools/shots/`。
